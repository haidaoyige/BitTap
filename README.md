# BitTap · Android NFC 冷钱包制作工具

**用一张 NFC 卡，保管自己的 BTC。**

离线生成私钥，加密存入卡片。版本 **0.5.0**（内部版本 15），支持 Android 9（API 28）及以上，仅支持 **BTC 主网**。没有联网权限、遥测、账户系统或私钥云同步。

本项目尚未完成独立资金安全审计，实体 NFC 和真实手机相机仍需验收。历史风险记录见 [0.4.0 安全评审](docs/SECURITY-REVIEW-0.4.0.md)，当前实现及清理边界见 [实现说明](docs/BITTAP-IMPLEMENTATION.md)。功能测试通过不代表已适合正式保管资金。

## 制作冷钱包

1. 点击“制作冷钱包”，输入并确认独立密码。至少 6 字符，建议使用更长的独立密码。密码无法重置，请与卡片分开保管。
2. 点击“生成冷钱包”。系统安全随机生成私钥，加密后验证恢复结果，成功后显示 SegWit 地址。地址栏内可查看其他三种地址。
3. 点击“开始写卡”，贴近一张已格式化为 NDEF 的可写卡片。程序检查实际容量和可写状态，有旧数据时明确提示覆盖；确认后再次贴回同一张卡片。写入后实时读回核对。
4. 通过“保存加密备份”把密文保存为文件。程序成功关闭文件并读回核对后，才将备份标记完成。取消或失败都不会标为完成。也可提前在写卡页保存备份。
5. 完成后返回首页，或点击“写入另一张 NFC 卡”，保存同一钱包。多张卡都是同一把私钥的副本，地址和密码不变。

返回按钮会提示先保存尚未备份的钱包。钱包会话只在内存中承接屏幕旋转等配置变化，不向 Android 页面恢复状态、缓存或数据库保存密文。进程终止、强制关闭、卸载或从最近任务移除会丢失未保存的制作进度，请先保存加密备份。返回首页时统一关闭私钥、清空输入和二维码、释放密文与待写卡数据并清除仍属于本 App 的剪贴板；用户主动导出的备份文件保留。Java/系统历史内存副本不能保证不可恢复擦除。首次充值前，建议重新读取并解密验证。

卡片建议 NTAG215/216，以实际 NDEF 容量检查结果为准。NFC 卡可被复制，公开地址可被读取；独立长密码用于保护加密私钥。App 不自动格式化。永久只读需主动开启并再次确认；仅支持识别到的 NTAG215/216，不能撤销，也不能防复制。模拟器可测试备份恢复和界面，实体 NFC 需真机。

## 读取与恢复

在“读取冷钱包”贴卡，或导入加密备份文件。新卡四个收款地址无需密码即可查看，界面标为“待解密核验”。输入制作时设置的密码后，本机完成解密、认证和地址核对，导出 **BTC 主网压缩 WIF**。收款地址与私钥二维码均可保存 PNG 图片，由系统文件选择器指定保存位置，关闭文件并读回核对后才提示成功。私钥图片保存前需单独确认；这是明文导出，不是加密备份。

- **使用支持 WIF 的钱包**：使用支持该格式及实际地址类型的钱包。不清楚操作时可向 AI 咨询步骤，切勿提供私钥或私钥二维码。
- **尽快转入新钱包**：复制或导入私钥会增加泄露风险。建议将全部 BTC 转入已完成备份的新钱包，确认到账后停止使用旧地址收款。
- **余额不符时核对地址类型**：核对钱包识别出的完整地址、地址类型和同步状态。四种地址余额分别记录，不会自动合并。

| 地址 | 构造 | 提示 |
| --- | --- | --- |
| Legacy / P2PKH，1… | 压缩公钥 HASH160 | 兼容传统钱包 |
| P2SH，3… | P2SH-P2WPKH | 兼顾旧钱包与 SegWit |
| SegWit，bc1q… | P2WPKH / Bech32 | 默认推荐 |
| Taproot，bc1p… | BIP341 key-only / Bech32m | 普通 WIF 导入不保证恢复；需确认目标钱包支持单私钥 Taproot |

这是独立单私钥钱包，没有 HD 派生路径。WIF 不携带地址类型，支持 HD Taproot 不代表支持本工具的单私钥导入。尚未完成外部钱包的单私钥 Taproot 恢复或实际花费验证。App 不查询余额、不签名或广播交易。收款地址二维码可经隐私提示后在外部浏览器查询链上余额，网站会获知该地址和网络信息。

## 加密与隐私

平台 `SecureRandom` 获取 32 字节，拒绝 0 和 >= 曲线阶 n 的值；随机源失败即停止，无弱随机回退。scrypt `N=32768,r=8,p=1,dkLen=32` + AES-256-GCM，128-bit tag；每次使用新的 16 字节 salt 与 12 字节 nonce。密码 Unicode NFC 规范化，保留大小写和空格。

**CG3 / CG2 / CG1 是项目自定义格式，不是 BIP38。** 通用钱包须先用本 App 或恢复工具解密为 WIF。格式、公开地址和完整性规则见 [docs/FORMAT.md](docs/FORMAT.md)。备份中不保存密码。低熵密码仍可能被离线猜测。

明文私钥 30 秒后隐藏，私钥二维码 60 秒后关闭，切后台清除解密结果、密码和二维码。返回首页还会清除仍属于本 App 的私钥或地址剪贴板；切换到钱包粘贴时保留原来的短时窗口。普通截图/录屏由 FLAG_SECURE 限制。私钥剪贴板标记为敏感内容，两分钟后及回到 App 时尽力清理自身仍有效的剪贴板；进程终止、后台限制和键盘历史意味着无法保证消除所有副本。用户明确要求保存图片后，待写出的 PNG 只在内存中等待文件选择结果，取消、失败、超时（3 分钟）、返回首页或销毁 Activity 时清除，不写入应用缓存或页面状态。进入系统选择器仍会锁定私钥并清除屏幕二维码；配置重建会取消待保存图片，需重新解密并保存。已导出的图片与备份由用户保管，本应用不会自动删除。Java/库对象的内存清理也不等同于硬件隔离。

## 编译与本机验证

需要 JDK 17、Android SDK 35 / build-tools 35.0.0，在 `local.properties` 配置 `sdk.dir`。首次编译下载依赖，APK 运行不需要网络。

```sh
./gradlew :core:test :app:testDebugUnitTest :app:assembleDebug :app:lintDebug :recovery:distZip
```

设备交互测试仅使用公开已知标量和测试密码，不向生产 APK 添加测试入口：

```sh
./gradlew :app:assembleDebugAndroidTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w io.coingift.android.test/io.coingift.android.SmokeRunner
```

验证结果和硬件待验项见 [docs/VALIDATION.md](docs/VALIDATION.md)。应用 ID 保持 `io.coingift.android`；同签名版本可覆盖安装，调试包与发行包使用不同签名，不能互相覆盖。切换前请先保存旧钱包的加密备份。

发行构建使用独立签名，须通过环境变量提供 `BITNFC_RELEASE_STORE_FILE`、`BITNFC_RELEASE_STORE_PASSWORD`、`BITNFC_RELEASE_KEY_ALIAS`、`BITNFC_RELEASE_KEY_PASSWORD`，然后运行 `./gradlew :app:assembleRelease :app:lintRelease`。缺少签名配置会停止打包；不会使用调试签名或交付未签名 APK。发行包关闭调试，不包含测试入口；签名私钥和密码由维护者单独保管，不放入仓库、APK 或源码分发包。发布与实机测试说明见 [docs/release/README.md](docs/release/README.md)。

## 独立离线恢复

解压恢复工具分发包，使用 Java 17。终端隐藏输入密码：

```sh
bittap-recover/bin/bittap-recover --inspect /本地/加密备份.txt
bittap-recover/bin/bittap-recover --decrypt /本地/加密备份.txt
```

CLI 兼容 CG3、CG2、CG1 和压缩 BIP38。只有输入 `SHOW` 才打印 WIF；终端回滚缓冲仍可能保留明文。新分发包命令为 bittap-recover；历史备份格式不变。

代码使用 Apache-2.0；依赖和标识来源见 [docs/THIRD_PARTY.md](docs/THIRD_PARTY.md)。本机测试通过不等于安全审计或实体卡验证。
