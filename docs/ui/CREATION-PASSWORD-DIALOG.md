# 制作密码弹窗与新版相机页面（v0.6.0）

本次修改采用已确认的暖白 / BTC 橙色原型。首页恢复较大的标题和卡片比例，让插图区域承接剩余高度，操作按钮和本地处理提示保留在下方。读取入口复用 `ic_nfc`，与“读取 NFC 卡片”使用同一图标。

制作页只保留公开钱包备注和相机增强选项。普通模式点击“生成冷钱包”后打开密码弹窗。增强模式先“开始相机采集”；完成 32 帧和匹配的最终照片采集后返回制作页，再点击“输入密码，生成冷钱包”打开弹窗。可以重新采集。失败、取消或进入后台会使未完成的采集失效，不会自动降级生成。

相机页采用新版双行标题、顶部实时预览及帧数标记、底部采集状态与独立隐私说明。预览显示真实 Camera2 数据；不会渲染原型中的模拟场景。最终照片在交付采集结果后立即清空和回收，只保留后续混合所需的摘要。已移除拍照后的人工照片确认步骤。

密码弹窗保留至少 10 个字符、两次一致校验和强度提示。弱密码仍可经单独风险确认后继续。两个输入框均不保存 Android 状态、不参与自动填充，并请求输入法不进行个性化学习。

取消、关闭、返回、旋转或进入后台会清空并解除密码输入框 / 按钮引用；失效按钮不能触发后台生成。生成前仍重新检查页面、相机状态、两次密码及备注，弱密码确认额外绑定当前输入修订和采集对象。开始后台生成前先清空并关闭密码弹窗，工作线程沿用原有可擦除密码数组管理。

所有密码弹窗与风险确认继续使用安全窗口、遮挡触摸保护和随键盘调整的滚动容器。输入密码会在内存中处理；清空 Java 文本和数组不等于保证系统、输入法或历史内存副本不可恢复。

此项改变交互和界面，不改变随机源混合、地址推导、CG3 加解密、NFC 数据格式或备份核验规则。四种语言同步更新。验收记录保存在工作区 `BitTap-security-validation/device-test-code21/`；相关修改已纳入 v0.6.0 发布范围；code22 另补齐了采集按钮的灰色禁用状态，采满 32 帧后才恢复橙色可点击。
