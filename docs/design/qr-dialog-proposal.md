# 二维码交互调整（已确认并接入）

2026-10-15 设计确认，2026-10-16 完成最终回归。用户确认底部卡片方案，二维码下方完整地址居中；原生 SegWit、嵌套 SegWit 的界面显示名称分别改为 SegWit、P2SH。实际地址构造、CG2 字段和已有备份兼容性不变。实现纳入 versionCode 6。

## 已修改源码

- 主地址栏取消单行限制与自动缩字，完整地址按行展示。
- 读取入口仅保留 NFC 和加密备份文件；移除加密文本复制、粘贴界面及路由。保留 NFC NDEF Text 记录格式兼容性。
- 地址、WIF 私钥复制均使用本次操作的唯一标签与原文读回核验。写入异常、读取异常、空结果、旧内容或多条内容均不提示成功，而提示“未能确认复制成功，请检查系统剪贴板权限后重试。”
- 未确认成功的私钥复制尝试仍保留本应用剪贴板归属标签与清理期限。返回首页只清理属于本应用的剪贴板，不清理其他应用内容。

## 已确认的设计

交互预览提供“底部卡片”和“居中弹窗”两个布局，推荐底部卡片，以延续 NFC 贴卡弹层风格。

- 页面与其他地址列表统一使用“展示地址”加扫描框图标，删除重复的收款二维码入口。
- 收款地址弹窗显示地址类型、BTC 主网、二维码、完整换行地址、解密核验状态；底部提供“复制地址”和“保存图片”。只有完成地址推导核验后，才显示“已与私钥核对，地址正确”。
- 用户已确认图片保存范围包括收款地址和私钥二维码。保存私钥图片前显示确认提示，说明图片包含明文私钥，持有图片的人可能转走 BTC。
- 原型使用公开标量 1 的地址及 WIF，禁止充值；复制、保存只演示反馈，不实际操作系统剪贴板或文件。

新入口、新弹窗、系统图片写入与成功反馈均已接入。文件选择器使用 ACTION_CREATE_DOCUMENT（image/png），无需新增存储权限。先关闭文件再读回逐字节核验，不自动写入相册或缓存；私钥 PNG 的内存等待副本仅在用户确认后生成，取消、失败、完成、超时、Activity 销毁或返回首页时清理。

为了在跳到系统文件选择器时继续清除屏幕二维码和已解密私钥，专用 PNG 副本最多仅等待 3 分钟，不保存在 savedInstanceState，也不经 RetainedFlow 承接。旋转或系统回收后需要重新保存图片。已导出的图片由用户自行保管，程序无法清理文件提供程序或云端产生的副本。
