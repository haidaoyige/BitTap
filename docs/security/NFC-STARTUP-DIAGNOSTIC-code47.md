# code47：NFC启动诊断与只读状态提示

2026-10-22。用户在小米15／Android16上的补充反馈：code46、新卡、未开启只读，点击开始写卡后约5秒，始终等待识别卡片，报“NFC操作超时”；重启手机后NFC恢复，再用BitTap又卡住。用户暂不方便USB连接，要求提供诊断APK。

## 结论边界

5秒来自reader启动期限，而非识别标签后15秒的数据I/O期限。当前无法取得问题手机线程／NFC服务堆栈，不能确定具体SDK或OEM阻塞点，也不能把模拟器测试当成该手机故障已修复。此版本专门采集固定阶段代码，不延长超时，不改变KDF、钱包格式或硬件锁位算法。

## 固定诊断代码

| 代码 | 含义 |
| --- | --- |
| NFC-Q | 控制任务排队或尚未进入系统调用 |
| NFC-A | 正在获取NFC适配器／初始化框架服务 |
| NFC-B | 正在查询系统NFC开关状态 |
| NFC-C | 正在调用enableReaderMode启动读卡模式 |
| NFC-D | 正在调用disableReaderMode停止先前模式 |
| NFC-R／NFC-I | 系统调用已返回：读卡已启动／停止或空闲 |
| NFC-S | 受控测试服务的默认阶段；不是实体后端通常使用的代码 |

阶段是进程内的固定字符串；读取阶段不会再次调用系统NFC API。启动超时先获取阶段快照，再取消当前扫描，使用现有底部错误弹窗和四语言资源展示。没有写日志文件、联网、保存线程堆栈、UID、收款地址、备注、密文或密码。超时后的迟到结果仍作废。

另外，系统后端只在确实尝试过enableReaderMode后执行对应disableReaderMode，避免单纯停止一个从未启用的reader时，在框架内创建并注册新Activity NFC状态。这是减少无效系统调用，不是已证实OEM启动卡住的根因修复。

## 只读反馈澄清与提示修订

用户确认：当时只打开只读开关，没有确认看到最终“本张卡片已永久只读，内容读回一致”，之后用BitTap能覆盖。现有流程仍有写入后不可逆确认与重贴验证，不能据此断言已成功硬件锁定的卡被解锁或绕过。

选择只读、但锁定未完成或未知时，完成页标题改为“钱包已写入，卡片尚未锁定”；只有VERIFY_LOCK成功才移除该待锁定标题。现有确认、跳过锁定继续备份、重试核验入口保留。没有自动执行用户尚未确认的永久锁定，也不阻碍先保存加密备份。芯片真实性与物理写保护仍需实体卡验收。

## 验证与实机步骤

测试结果与APK摘要记录于工作区`BitTap-security-validation/code47-nfc-startup-investigation/validation.json`。原15秒I/O期限、取消、迟到结果丢弃和已只读卡预拒绝保留。测试替身不代表小米实体NFC验收。

安装诊断版后，先重启手机恢复系统NFC；先不贴卡，点击开始写卡。如果约5秒即超时，反馈错误中的固定阶段代码即可；不需要提供密码、私钥、二维码或钱包文件。如果没有启动超时，再贴无资金测试卡，区分是否进入“正在检查卡片”。系统NFC再次失去响应时停止反复尝试，之后需要真实设备日志才能继续定位。

框架reader mode启停实现依据：[AOSP NfcActivityManager](https://android.googlesource.com/platform/packages/modules/Nfc/+/refs/heads/main/framework/java/android/nfc/NfcActivityManager.java)。此实现不能说明小米OEM内部实现与AOSP完全相同。
