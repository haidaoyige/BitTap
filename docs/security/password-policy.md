# 新建钱包密码格式校验

本次只修改新建钱包的密码要求与录入提示，不修改加密格式、KDF 参数或旧数据的解密规则。

- 至少 10 个 Unicode 码点，保留最多 1024 个 UTF-16 单元的原有输入上限。
- 必须同时包含 ASCII 大写字母 A–Z、小写字母 a–z、数字 0–9，以及 Unicode 标点或符号。空白、换行、控制字符本身不计作特殊字符。
- 五项规则随输入逐项更新。只有格式通过且两次输入一致，生成按钮才启用；键盘提交与实际生成入口仍由核心校验拦截。
- 中、英、日、韩四种语言同步提示。满足格式不等于已证明密码强度；对明显重复等弱模式仍保留原有风险确认，确认不能绕过格式要求。
- 检查器不保存输入、不创建额外的不可变密码字符串；退出、后台、旋转与生成时沿用现有输入清理流程。
- CG1/CG2/CG3 及现有 BIP38 恢复不套用新建密码规则。兼容测试覆盖旧六位密码、十位纯数字与不满足新规则的长密码。

## 验证

核心、App 与恢复工具单元测试共 87 项通过（核心 67、App 14、恢复工具 6）。Debug App 与设备测试包编译通过；lint 无错误，保留既有的 UnusedResources 与 SetTextI18n 两条警告。

Android API 35 独立模拟器：四语言创建弹窗 157 项断言、密码格式与弱模式确认/旧密码恢复 109 项断言全部通过，共 266 项。覆盖每类字符缺失、两次输入不一致、实时按钮联动、符合规则的十位密码正常生成、旧六位密码通过实际恢复页面解密，以及取消、后台、旋转、悬浮遮挡和过期回调的清理与拦截。

验证仅使用公开测试口令与一次性测试钱包，不使用真实资金。设备日志及截图保存在仓库外的 `BitTap-security-validation/password-policy/`。
