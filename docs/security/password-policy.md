# 新建钱包密码格式校验

新建钱包的校验与强度评估使用与 KDF 相同的 Unicode NFC 规范化表示。不修改加密格式或 KDF 参数，不增加旧卡片兼容分支。

- 新密码只接受可见 ASCII：大写字母 A–Z、小写字母 a–z、数字 0–9 及半角标点符号（U+0021–U+007E 中的非字母数字字符）。至少 10 位、最多 1024 位，并且四类都必须包含。
- 中文、日文、韩文、重音字母、emoji、全角字符、空格、换行及不可见字符全部拒绝。先检查原始输入的字符范围，再规范化检查长度、格式和强度，避免 Kelvin 等非 ASCII 字符经规范化变成 ASCII 后绕过限制。被允许的 ASCII 字符在 NFC 下不变。
- 五项组合规则随输入逐项更新，不支持的字符另显示明确错误；只有全部通过且两次输入一致，生成按钮才启用。输入与粘贴都不会静默删除或替换字符，键盘提交与实际生成入口仍由核心校验拦截。
- 中、英、日、韩四种语言同步提示。满足格式不等于已证明密码强度；对明显重复等弱模式仍保留原有风险确认，确认不能绕过格式要求。
- 检查器不保存输入；已经是 NFC 的内容直接检查原序列，避免实时校验产生额外的不可变密码字符串。需要规范化时 Java API 会产生不可原地清零的字符串，不承诺清除所有 JVM 副本。退出、后台、旋转与生成时沿用现有输入清理流程。
- 密码规范化由同一核心函数提供给格式检查、强度评估和 KDF；恢复入口不套用新建格式门槛，未为此新增兼容逻辑。

当前后续开发版本仅由用户手动输入并确认密码，不提供随机生成密码、复制密码或保存勾选入口；字符限制与强度评估保持不变。
