# 0.7.0 发布汇总（2026-10-22）

内部版本50，产品功能以code49为基线；版本文档更新、源码公开与正式来源验证不代表新增实体硬件验收。当前细节见 [0.7.0说明](../release/v0.7.0/RELEASE-NOTES.md)。原私有仓库Issue不再作为私密漏洞渠道，使用SECURITY.md邮箱或可用的GitHub私密报告入口。

# 最新针对性修订：code49（2026-10-22）

小米15／Android16反馈NFC-LOCK-L3-TIME后又出现NFC-D。code49将NTAG215／216锁定改为显式芯片页流程，移除通用Ndef.makeReadOnly／canMakeReadOnly调用；修正动态锁页保留字节写回，并逐步读回，最终全部核验条件保留。没有问题手机堆栈和实体射频验收，仍需实机确认，不能把此版本称为已证明修复OEM服务阻塞。详见 [code49 专用锁定流程与测试边界](NFC-NTAG-LOCK-code49.md)。

# 最新诊断修订：code48（2026-10-22）

用户报告点击“确认永久锁定”后提示“写入成功，锁定未确认”；此前不能等同于未开启只读。code48补充LOCK／VERIFY_LOCK的固定阶段与原因代码，保留unknown与全部锁定判定，不修改锁位算法。没有问题手机的日志或实体锁位证据，根因仍待定位。详见 [code48 锁定诊断](NFC-LOCK-DIAGNOSTIC-code48.md)。

# 最新诊断修订：code47（2026-10-22）

小米15／Android16实测仍在NFC启动阶段约5秒超时且系统NFC失去响应；code46未通过该实体设备验收。code47提供固定阶段诊断及明确的“已写入、尚未锁定”标题，供无USB条件下定位，不宣称根因已修复或硬件锁定已验收。详见 [code47 诊断范围](NFC-STARTUP-DIAGNOSTIC-code47.md)。

# 最新本地修订：code46（2026-10-22）

针对小米15／Android16上已只读卡重写导致ANR的报告，提前拒绝已只读卡，将应用显式NFC适配器启停移出主线程并设置5秒启动期限；处理阶段保留取消，写入和锁定不确定结果不误报成功。正常可写卡仍实时读回核对，原数据I/O15秒期限保留。未取得该手机ANR堆栈，未进行实体射频验收，不能据此宣称OEM ANR已彻底关闭。详见 [code46 实现与边界](NFC-READONLY-ANR-code46.md)。

## 后续处理边界

- BTA-02、04 仍直接涉及误收款或私钥明文访问。改变出口或辅助功能行为前，仍按用户要求先确认原型。
- BTA-01 不将“格式要求已加强”写成“密码熵已保证”，也不擅自禁止用户已经允许的格式合格弱模式。
- BTA-08 需要仓库强制保护与后续正式发布的最终提交／CI 对应验证，不涉及 Android 页面。
- BTA-11 需同步文档并验证实际收发；未经用户明确授权，不发送测试邮件。
- BTA-12 不将“不计划修复”写成“已修复”。

“仅核验地址”的独立路径仍未实施，它是 BTA-02 及减少私钥暴露的可讨论方案，不新增为重复漏洞编号。随机长密码按钮也未确认实施，不算已经批准的开发任务。
