# BTA-05 / BTA-14 本地修订

## BTA-05

- 实际解密结果交给前台会话时启动基于 elapsedRealtime 的单调时钟。
- 连续 60 秒无有效触摸、按键或按钮操作，或从解锁开始满 120 秒时，按较早的期限结束会话。绘制、倒计时、程序查询、打开提示均不延长绝对期限。
- 对主页面及私钥、复制确认、保存确认等受保护弹窗的输入统一计时；被遮挡而拒绝的手势不记作有效操作。
- 查看、复制或开始私钥图片导出前同步复核期限，避免主线程计时回调稍晚时绕过锁定。
- 到期关闭私钥及确认弹窗、清空持有的 scalar 数组、私钥文字及二维码位图、待导出图片，并尝试清除本 App 拥有的私钥剪贴板内容。系统拒绝剪贴板访问时沿用返回前台重试机制。
- 保留已读入的加密钱包以供再次输入密码。地址恢复为待核验展示，不给钱包备注添加核验标签。
- “私钥已恢复”页面不展示倒计时或计时提示栏，后台时限校验保持启用。
- code26 使用统一暖白橙色底部弹窗显示“私钥已自动锁定”，分为 60 秒空闲和 2 分钟上限说明，仅点击“知道了”关闭。后台、返回首页及旋转原有清理行为保持有效，不序列化私钥或计时状态。

这里的清理是释放引用及清空应用所持有的可变缓冲区，不能承诺 JVM、系统服务或第三方接收方中所有历史副本都被物理擦除。已由用户明确保存的私钥图片也不会被自动撤回。待保存的私钥 PNG 缓存及其后续文件任务受原会话期限约束，进入系统文件选择器不会将这一期限重新延长到三分钟。

## BTA-14

原先文件字节读写已在后台线程执行，缺口在单个 provider 调用可无限阻塞并长期维持 fileBusy。修订如下：

- 从加解密单线程队列分离文件任务；文件工作池最多 2 个 daemon worker，无等待队列。故障任务不会无限增长，也不占用生成或解密队列。
- 每项任务使用带 CancellationSignal 的 AssetFileDescriptor 打开文档，登记持有的 descriptor 和 stream；取消时发出信号并尝试关闭资源。
- 取消信号及关闭操作本身也可能阻塞，因此放在有界后台清理池，主线程不等待 provider 返回。
- 每次导入、备份保存、二维码图片保存与读回核验的总时限为 15 秒。支持取消、返回、退后台/销毁取消，并立即解除 fileBusy。
- 界面仅接收当前任务的结果，且接收时再次核对单调期限。取消、超时及旧任务的迟到回调均不能更改当前钱包或标记备份成功。
- 备份只有完整写入、成功关闭并精确读回核验后才标记已保存。取消和失败不标记；原生“保存失败”弹窗一直保留到用户确认。
- 私钥 PNG 的任务缓存取消时立即填零，结束时再次清理；worker 只持应用 Context/弱界面引用，避免故障 provider 长期持有 Activity。

外部 provider 若完全不响应信号或关闭，其底层调用仍可能占用有界 worker；App 可以继续其他操作。两个 worker 都被占用时，新文件任务快速失败而不是继续排队；需要换用正常文件服务或重启 App。取消也不能撤回 provider 已写入的字节，因此错误弹窗明确要求检查保存位置。

## code27：密码按钮原位加载

撤销 code26 新增的独立加解密处理弹窗。原密码弹窗在提交后继续显示，原按钮禁用并改为灰色，图标改为旋转指示器，文案为当前语言的“正在处理，请稍后...”。密码框与显示密码按钮被锁定，真实 Editable 内容仍在复制至受控待处理缓冲区后立即清空，仅用固定长度的点状提示占位；不因保留原弹窗延长明文输入的保留时间。

取消、关闭与系统返回均撤销当前结果授权、清理口令并关闭原密码弹窗。处理失败恢复原按钮及空输入框，允许重试；成功后关闭原弹窗进入后续页面。后台/旋转继续清理，动画在按钮恢复或视图移除后停止请求帧。自动锁定、地址核验及文件处理的逻辑和样式保持不变。

91 项单元测试、API35 四语言原位加载 112 项检查，以及完整生成流程 157 项检查通过；专项有覆盖重叠，不相加作独立安全用例数。code27 已沿用原发行签名另行打包，code26 旧文件未覆盖。最终 code27 APK 在 API35 上再次通过 112 项原位加载检查，已安装包与交付文件 SHA-256 一致。记录位于仓库外 `BitTap-security-validation/device-test-code27/`，此前源码专项记录位于 `BitTap-security-validation/device-test-inline-loading/`。

## code26 界面更新

生成/加密和解密/核验使用带原生不定进度指示器的 App 底部弹窗，不显示虚假百分比。取消按钮在 busy 期间仍可使用，取消沿用 epoch 失效及待处理口令清理；结果只由现有后台加解密回调提交。自动锁定在清理会话后显示同款提示，不自动关闭，不更改截止时间规则。四种语言同步更新。文件失败提示仍使用原生确认框。
