# code46：已只读卡重写时的界面无响应修订

2026-10-22。用户实测：小米15、Android16，制作流程打开永久只读选项后，扫描已经只读的卡片出现“应用无响应”。未取得该实体设备的 ANR 堆栈，因此下述为已确认代码缺口的修订，不能据此认定 OEM 故障根因已被实机复现或完全排除。

## 已确认的缺口与修订

1. 原流程连接NDEF后才检查可写性。改为先检查发现时缓存的可写状态和容量，已经只读的卡在应用发起connect前拒绝；无论是否打开永久只读选项均相同。不会对这条拒绝路径执行写入、覆盖确认或锁位操作。错误使用现有底部弹窗，提供中英日韩四语言。
2. 原代码仍在主线程调用NFC适配器的获取、状态检查与reader mode启停。它们涉及系统服务调用，原15秒数据I/O超时无法解救已阻塞的主线程。新增独立的、有界的NFC控制器，最多1线程与1个排队任务，同一控制器只处理最新启停意图；不与密码工作器或卡片I/O共用线程。不在主线程触发任何应用显式的NFC适配器调用。
3. Reader启动5秒未返回时，主线程放弃此次扫描并显示现有超时提示；停止调用即使迟迟未返回，也不阻塞该错误弹窗。迟到的启动完成须再次核对控制器版本、当前epoch与扫描状态；取消或超时后补执行停止，不能重新进入流程。
4. 原扫描弹窗在处理阶段禁止取消。保留现有取消、关闭与系统返回入口。取消写入后显示“写入结果未确认”；取消锁定保留“状态未知”。取消与超时均不表示硬件操作已回滚。
5. CHECK失败／取消、WRITE失败／取消后清理候选卡；迟到任务仍经过原身份、epoch、创建会话和单调时限校验，不计作写入成功，不满足强制备份。

可写卡仍在连接后重新检查状态，写入前读取真实旧内容并与候选数据比较，写入后通过真正的NFC读取比较完整NDEF；不以发现缓存作为写入成功证据。再次贴卡写入时也先检查可写性，防止检查后卡片变成只读。读取已有只读钱包不受可写检查限制。

未修改钱包加密格式、KDF、私钥生成、地址推导、只读锁位算法或强制加密备份要求。版本名0.6.2，内部构建号46，同原签名；未发布GitHub。

## 验证边界

新增单元测试覆盖：只读拒绝前不connect/read/write/close、检查到写入间变只读、容量不足、可写卡实时读回、旧内容变化、回读不一致、控制服务启停阻塞、最新意图合并、迟到回调、销毁与有界队列。

设备探针直接执行生产的卡片检查与Activity完成回调，并使用受控Card／NFC Service替身；验证只读选项开关两种情况、失败后无覆盖确认、候选及忙状态清理、密码线程独立、控制服务阻塞期间错误弹窗可关闭、真实5秒启动超时、处理中的可见取消及迟到写结果丢弃。模拟器不具备真实NFC射频链路。

最终结果及同一APK摘要见工作区 `BitTap-security-validation/code46-readonly-anr/validation.json`。Android16 Google镜像需要另行接受Google镜像许可，本次没有接受或安装该镜像；不能把Android12／15模拟器结果称为Android16或小米HyperOS实体验收。

仍须在报告问题的小米15／Android16上，用无资金测试钱包及同一张已只读卡复测：开启只读选项→扫描已只读卡→应提示更换可写卡；关闭选项重复→同样拒绝；取消提示→仍能使用正常文件恢复／新卡检查。已只读卡应还能正常读取已有钱包。正常可写NTAG215／216的写入、读回和永久锁定需实体卡验收。

应用控制线程不能保证系统、OEM驱动或Android框架自己的生命周期回调永不阻塞；若仍出现ANR，需要对应设备的系统ANR日志定位具体堆栈。对完全不返回的底层调用不创建无限替代线程；后续NFC尝试会快速失败，可能需恢复系统NFC服务或重启进程。

## 实现依据

- Android NDEF的isWritable读取发现时的缓存，无RF通信；getNdefMessage为阻塞I/O。因此缓存仅用于拒绝，不用于确认写入成功。[AOSP Ndef实现](https://android.googlesource.com/platform/frameworks/base/+/28319c0/core/java/android/nfc/tech/Ndef.java)
- reader mode启停会调用系统NFC服务；框架自身也在Activity生命周期回调中执行部分服务调用。[AOSP NfcActivityManager实现](https://android.googlesource.com/platform/packages/modules/Nfc/+/refs/heads/main/framework/java/android/nfc/NfcActivityManager.java)
