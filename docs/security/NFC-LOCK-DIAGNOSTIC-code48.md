# code48：永久只读失败的阶段与原因诊断

2026-10-22。用户补充：code47能写入卡片；点击“确认永久锁定”后，一直贴着同一张卡，即弹出“写入成功，锁定未确认”。此前把这句等同于仅开启开关、未进行锁定不准确。该提示也会在LOCK或VERIFY_LOCK的异常、超时、取消时显示，不能单凭它判断卡片是否已经锁定。

用户暂不方便USB连接，没有实体设备线程或NFC系统服务堆栈。code48补充诊断，未确认根因，不能宣称小米15／Android16或实体卡永久锁定已经修复／通过验收。

## 确认的代码缺口

此前LOCK与VERIFY_LOCK捕获的所有异常均被同一底部弹窗代替，失败阶段及原因没有展示。code48保留原“写入成功，锁定未确认”及备份入口，在其内部追加固定代码与本地化解释，供无USB场景定位。

格式：`NFC-LOCK-阶段-原因` 或 `NFC-VERIFY-阶段-原因`。

| 阶段 | 对应步骤（包含该步骤的连接与关闭） |
| --- | --- |
| 0 | 尚未进入具体锁定步骤／受控测试 |
| L1 | 核对刚写入同一卡片的完整NDEF内容 |
| L2 | 检查芯片型号、镜像与访问配置 |
| L3 | 调用NDEF永久只读操作 |
| L4 | 进入硬件锁定辅助流程 |
| H1 | 连接硬件页读取接口 |
| H2 | 读取GET_VERSION并核对支持型号 |
| H3 | 读取配置区，检查已有镜像／访问保护 |
| H4 | 读取、设置并写入动态锁定位 |
| H5 | 设置配置区CFGLCK锁定位 |
| H6 | 读取并写入静态锁定位 |
| V1 | 最终核验：核对钱包NDEF内容 |
| V2 | 最终核验：实时读取静态、动态、CC与配置锁位 |
| V3 | 最终核验：检查NDEF发现状态是否为只读 |

原因：`TIME`超时、`LOST`卡片连接断开、`BUSY`工作器不可用、`CANCEL`用户取消、`IO`通信异常、`CARD`卡片条件不满足、`STATE`锁定或核验未通过、`OTHER`其他异常。`CARD/STATE/OTHER`仍提供保守的通用解释，不能据此推断具体厂商固件故障。

阶段为固定枚举，原因只按异常类型映射。UI不输出异常原文；不把UID、地址、钱包备注、密文、密码或私钥拼接入诊断。阶段只存在任务内存中，不新增文件日志或联网。

## 保持的安全判定

- 钱包写入成功与永久只读成功继续分开；LOCK/VERIFY_LOCK未通过仍为unknown，不能变为locked。
- 不改变硬件锁定位掩码、写入顺序、NDEF makeReadOnly调用、卡片匹配、实时内容比较及最终核验条件；不增加试写来验证锁定，避免未知状态下破坏钱包。
- 不移除或忽略NDEF只读检查来强行获得成功；该检查可能受到发现状态缓存影响，但目前没有实体证据表明它就是本次失败点。
- 不重复或自动执行用户未确认的不可逆锁定；取消、超时、后台和旧结果的安全规则保留。
- 备份入口保留。正常加密格式、KDF、私钥生成及地址核验没有修改。

新增阶段保留／取消后拒绝更新的单元测试；设备替身通过生产完成处理器注入各类LOCK与VERIFY_LOCK故障，核对四语言固定阶段与原因、不显示异常原文、保留unknown、已写入计数不回滚且不能绕过强制备份、底部弹窗样式和FLAG_SECURE。
