# code45：NFC 隔离与弱密码模式识别

2026-10-22，基于本地 code44 审计后的修订。版本号保持0.6.2，内部构建号45；没有发布GitHub版本，没有修改仓库权限。

## NFC 任务边界

- NFC使用独立、进程共享、最多1个工作线程的执行器，没有等待队列。加解密和本机核验记录不再与NFC竞争同一队列。
- 15秒总时限从识别到标签、实际开始操作时计算，涵盖连接、检查、写入、读回及资源关闭；等待用户贴卡期间不启动计时。期限使用单调时钟；UI定时解除等待，结果接收点再次核对期限。
- NDEF和MifareUltralight连接在connect前登记。取消、后台、首页、离开流程或销毁时使任务失效，并在独立有界清理池尝试关闭连接、打断等待；关闭本身也不能阻塞主线程。Ultralight另设3秒单次通信期限。
- 工作任务只持标签、公开UID及加密负载、候选数据快照；不持Activity、密码或私钥会话。界面通过弱引用、当前任务身份、epoch、当前创建会话及期限检查接收结果。
- 超时／取消后的成功回调不能导入钱包、增加写卡计数、建立核验记录、确认永久锁定或满足备份要求。写入失败后清理候选卡片，重新写入必须重新检查；锁定／锁定核验中断保持“状态未知”。
- 原有页面、按钮、写入确认和备份要求保留。新异常文案使用现有底部提示样式，提供中英日韩四语言。

底层驱动如果完全不响应中断和close，可能持续占用这一个NFC线程。新的NFC任务快速失败，不新增无限线程或排队，不阻塞加解密。可能需要移卡或重启进程恢复NFC。取消不能撤销已经发送给卡片的写入或永久锁位；不能把UI解除等待解释为硬件已回滚。

## 密码模式识别

新密码仍至少10位，仅允许可见ASCII，且含大写、小写、数字、半角符号。规范化、KDF参数和卡片格式不变。

扩展对常见词加数字／标点、常见字符替换、重复核心和占主体的键盘／数字序列的弱模式识别。处理使用临时CharSequence视图，不为识别再生成完整明文密码String。沿用现有弱密码确认弹窗，仍允许用户确认后继续。

这只是启发式提醒，既可能漏判也可能误判，不能证明用户密码熵。不会存储密码、联网查询密码或给出固定破解时间。用户取得加密备份后可离线猜测，App内错误次数限制不能阻止这种尝试。

## 验证与后续验收

新增NfcIo单元故障测试，以及Android12／15专用故障探针：连接阻塞、真实15秒截止、取消时close、无响应驱动下拒绝新任务、加解密线程仍可运行、旧写入结果失效、锁定超时不误报和后台取消。设备探针使用受控传输替身，不冒充实体NFC验收。

同时回归四语言创建／恢复、弱密码确认、私钥门禁、自动锁定、地址核验和现有完整钱包流程。本轮最终116项单元测试（核心85、Android25、恢复6）通过；Android12／15的NFC故障专项各62项断言通过。最终APK已另补NFC、弱密码、完整流程和首页复测通过；测试阶段与APK摘要在交付记录中分别列明。最终结果与日志位于工作区外`BitTap-security-validation/code45-nfc-password-hardening/`，以该目录最终validation.json为准。

实体卡验收应使用无资金钱包及可消耗测试卡，至少覆盖：

1. NTAG215／216正常检查、写入、实际读回和另一台设备恢复；容量不足与已有数据必须按当前交互拒绝或先确认。
2. 连接、写入、读回中移卡及关闭NFC；不得误报成功。重新贴卡后检查实际内容，部分写入不能作为已完成钱包使用。
3. 锁定中移卡，界面必须保持未知；移开再贴、重新上电后检查NDEF和硬件锁位，再用另一设备尝试覆盖。卡片永久锁定测试不可逆。
4. 故障后可继续从正常文件恢复、执行密码核验或生成钱包；不得被NFC工作线程拖住。
5. 相机权限拒绝、重复帧、中途退出及不同机型的采集流程。相机只是补充源，不宣称量化熵增益。
6. 外部钱包先核对四种地址；链上花费需要另行授权，不在自动化测试中使用真实资产。
