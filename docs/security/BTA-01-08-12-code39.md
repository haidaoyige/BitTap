# BTA-01 / 08 / 12 — internal code39

This change preserves the current Android UI and interaction. It does not close
all remaining security findings or guarantee funds safety.

## BTA-01: uniform higher KDF cost

CG encryption and decryption now require exactly scrypt N=32768, r=8, p=3,
32-byte output. The p value is present in the authenticated header. All other
profiles, including the earlier internal-test p=1 profile, are rejected during
inspection before KDF work. The owner explicitly waived recovery compatibility
with these internal-test cards and backups; no fallback or automatic downgrade
exists. Re-create test wallets with the matching app/recovery tool.

The nominal working memory remains around 32 MiB plus implementation overhead;
the p increase raises CPU work. Device emulator measurements are recorded in the
local validation attachment and are not benchmarks of all physical phones.

Password character requirements and weak-pattern confirmation remain unchanged.
A copied encrypted backup still permits offline guessing. This raises guessing
cost; it does not guarantee password entropy or close BTA-01 in its entirety.
Reference: [OWASP scrypt guidance](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#scrypt).

## BTA-12: compressed BIP38 import boundary

`Bip38Importer` adapts bitcoinj 0.17.1's Apache-2.0 decryption routines. The
upstream parser still checks Base58Check, lengths, type and reserved flags.
AES/scrypt processing follows BIP38 for non-EC and EC-multiplied records,
including lot/sequence handling and NFC password normalization.

Instead of returning the upstream private ECKey wrapper, which excludes scalar
1, the importer validates the raw result in [1,n-1], derives a public-only key,
and verifies the standard mainnet P2PKH address hash before returning any key.
Wrong passwords, invalid scalars, wrong-network address hashes and malformed
records fail closed. Uncompressed BIP38 remains unsupported, as before.
Owned mutable secret buffers are cleared; Java/library immutable copies remain
part of the documented BTA-04 boundary.

Tests include both official compressed BIP38 vectors and independently generated
public vectors: scalar 1, scalar 2, n-1, Unicode NFC, both EC modes, wrong
network, zero and n. Wrong passwords, reserved flags and checksum corruption are
also checked. Never fund test-vector addresses.

## BTA-08: CI identity and signing gate

- Repository Actions allow only the four reviewed exact action SHAs, require SHA
  pinning, use read-only default permissions and cannot approve PR reviews.
- Release preparation checks exact source commit, same repository, CI event,
  completed success and the actual verification job in the current run attempt.
- The unique, unexpired comparison artifact must identify the matching commit
  and carry a SHA-256 digest. The downloaded ZIP must match that digest before
  its two fixed members are read. Unexpected members and excessive sizes fail.
- Local Gradle reconstruction receives no `BITNFC_RELEASE_*` environment and
  builds unsigned. The APK payload and recovery ZIP must match independent CI
  **before** apksigner receives the existing local signing identity.
- Source commit, CI run/attempt, verification job, artifact ID/digest and output
  hashes are recorded with the signed release manifest. Release preparation
  does not publish or upload a GitHub release.

Branch protection/rulesets remain unavailable for this personal private repo on
its current GitHub plan (API returns 403). The auditor's existing write access
is retained per owner instruction until a read-only SSH public key is supplied.
These remain open BTA-08 governance limits. The gate does not make unreviewed
source trustworthy or protect a compromised signing host.

## Validation commands

Use the pinned JDK/toolchain and strict Gradle dependency verification. Run core,
Android policy and recovery tests; the current Android UI/device suites; the
independent `check_interop.py`, `check_addresses.py`, `check_bip38.py`; release
provenance/tamper tests; packaged-license and runtime-OSV checks. The final
submitted source must pass independent CI and release payload comparison.

Physical NFC write/interruption/permanent-lock tests and external-wallet spending
remain separate hardware/funds-path acceptance work. UI regression and simulator
success must not be described as physical entropy certification or full security
audit closure.
