# code49：NTAG215/216 专用永久只读流程

2026-10-22，0.6.2／内部号49。本地原签名测试包，未发布GitHub。

## 反馈与结论边界

小米15／Android16：code48点击“确认永久锁定”，保持卡片贴合，出现NFC-LOCK-L3-TIME，随后NFC-D。L3包含通用NDEF锁定步骤的连接、makeReadOnly和关闭；D是关闭读卡服务步骤。因此已把问题缩小到该路径，但没有设备堆栈，无法分辨具体阻塞的Binder调用，也不能据此证明手机固件根因。

code49实施针对性替换，不再调用平台Ndef.makeReadOnly或canMakeReadOnly。仍需该手机和实体卡复测，不把模拟器或页模型当成真实硬件验收。

## 修改

- 仅接受GET_VERSION精确匹配的NTAG215／216；未知型号不尝试写锁。版本响应本身不是芯片真实性证明。
- 写锁之前，核对刚写入同一张卡的完整NDEF内容；检查CC、镜像、访问保护及已冻结的部分锁位。所有目标预检查通过后才开始不可逆写入。
- 专用流程依次设置CC只读标志、动态锁位、CFGLCK配置锁、静态锁位。每一步立即实时读回比较；完整钱包用户区不被本流程改写。保留已有有效配置位。
- 修复动态锁页RFUI写值：读回末字节BD不能原样写回，写入时为零；其他保留位也按型号清零。
- CFGLCK需移开卡片并重新贴回，使卡片重新上电后核验。最终依然要求完整钱包内容、硬件锁位及NDEF发现状态全部符合，才显示已永久只读。不用试写破坏钱包来证明写保护。
- 新增H0阶段表示CC写入／读回，其余H1至H6诊断保留。L3枚举为历史诊断兼容保留，生产锁定路径已不再进入L3。阶段包含对应资源关闭，不等价于单一系统调用。
- 原15秒I/O期限、3秒芯片通信设置、取消、单工作器上限和迟到结果丢弃保持。NFC-D仍表示服务停止未及时返回；应用不能承诺强制恢复系统NFC服务。
- 钱包写入与只读成功仍分开；取消、超时、读回不一致和未知结果不会标记locked。强制备份、私钥生成和加密格式未改。

## 验证

新增9项单元测试，使用按芯片页权限建立的独立模型：两种型号所有用户页写保护、钱包数据不变、保留字节、移开重上电后配置冻结、重复执行、未知型号／异常配置拒绝、部分冻结预检查、应答但未编程、通信异常及截断读回失败。页模型不能证明真实卡片行为。

原NFC控制测试的清空辅助方法曾用两个近似executor快照判断空闲，引发测试自身的瞬时竞态；改为要求20毫秒稳定空闲，3秒上限及主线程响应断言未放宽，产品调度代码未变。

最终137项单元测试和设备回归明细、Lint、APK权限签名及字节码检查，见工作区BitTap-security-validation/code49-ntag-lock/validation.json。字节码检查确认不存在平台NDEF通用锁定调用，正式APK不含设备测试探针。此前code47 Android15可见取消1秒计时不稳定仍应保留跟进，单轮通过不能证明该问题消失。

## 实机步骤

安装后先重启手机，清除上一版已经卡住的NFC服务状态。使用没有资金的新测试钱包和可写NTAG215／216；保存加密备份。确认永久锁定后，按提示真正移开卡片再贴回。只有最终明确“本张卡片已永久只读，内容读回一致”才是应用确认状态。如再次失败，只需反馈完整固定诊断代码，不发送钱包数据。旧卡可能已经部分锁定，不为诊断覆盖已有钱包。

公开依据：[NXP NTAG213/215/216 数据手册 Rev3.2](https://www.nxp.com/docs/en/data-sheet/NTAG213_215_216.pdf)，§8.5、§8.8。没有使用未公开的AN11456，也不宣称已按其完成NFC设备兼容性认证。
